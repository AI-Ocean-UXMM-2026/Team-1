ISSUE REPORTED:
═══════════════════════════════════════════════════════════════════════════

When clicking "Customer Complaints" in the manager sidebar:
  ❌ Page redirects back to manager home
  ❌ Dashboard doesn't load
  ❌ Can't access complaints


ROOT CAUSE:
═══════════════════════════════════════════════════════════════════════════

The ComplaintsApp component was hardcoded to use role "support":
  
  const workspace = useOperationsWorkspace("support");

Managers have role "manager", not "support", so the workspace hook
detected a role mismatch and redirected them to manager home.


SOLUTION:
═══════════════════════════════════════════════════════════════════════════

Modified ComplaintsApp to dynamically detect the user's actual role:

1. Added state to track user role (manager or support)
2. On mount, query user's profile from database
3. Detect if user is manager or support
4. Use the correct role with workspace
5. Show loading screen during detection
6. No more redirects!
